# 围绕 SoC/SDMA 目标的项目工作开展计划

修订日期：2026-10-12。依据用户确认的修订稿，将第一次项目工作思路与后续优化建议整合于此。

本文件负责“怎样逐步实现项目目标”。gem5 整体构成与特征的学习范围由独立的 [gem5 研究计划](gem5-research-plan.md)维护；项目目标见 [项目上下文](../project-context.md)，实际完成情况见 [当前进度](../records/PROGRESS.md)。

## 目标与推进原则

逐步形成“把架构问题转成模型，通过实验解释性能，并判断结论可信范围”的能力。

保留四项相互配合的工作：学习工具、理解 SoC 机制、积累可组合模型、研究目标 SDMA/SoC。按能力和研究问题进入后续阶段，不预设固定周数，也不要求先学完整个 gem5 才开始实验。

## 阶段工作与完成条件

| 阶段 | 怎样开展工作 | 阶段产出与进入下一阶段的条件 |
| --- | --- | --- |
| 1. 掌握基本运行 | 核查并准备 Linux 运行环境，使用固定版本构建 gem5；运行简单 SE 系统和内存流量示例，学习修改配置、定位错误和读取统计；结合实例认识 SimObject、EventQueue、Port、Packet、Timing 和 Statistics | 能重复运行；能解释实际使用的配置、退出原因、主要统计及时间口径 |
| 2. 用小实验理解性能机制 | 先研究注入率、服务能力和饱和；再分别研究 outstanding、请求粒度、读写比例、有限队列及反压；详细 DRAM 行为按问题引入 | 能在运行前提出预期，并用对照实验解释吞吐和延迟变化 |
| 3. 建立简单 SoC model | 组合 CPU、Cache、互连和内存；先研究单一请求源，再增加共享资源和竞争；把实验现象与 soc_study 中的模块职责对应起来 | 能说明请求经过哪些模块、在哪里等待、主要瓶颈是什么，以及改变一个模块为何影响系统 |
| 4. 建立通用 DMA 模型 | 从一次搬运出发，表达读请求、返回数据、有限缓冲、写请求、outstanding、反压和完成通知；逐步加入读写重叠 | 数据和完成语义正确；资源上限有效；能够解释有效拷贝带宽与总读写流量的区别 |
| 5. 研究目标 SDMA | 明确目标问题和已有资料，按需加入命令队列、取指与解析、流水、地址翻译、竞争和通知；审查官方 SDMAEngine 的可复用部分及简化 | 有明确的功能、时序和资源假设；目标性能结论有相应校准依据，缺少依据的部分保留为机制模型 |
| 6. 扩展到较大 SoC | 围绕具体问题增加多请求源、多通道内存、共享 Cache、互连、QoS 或软件交互，研究端到端路径和资源竞争 | 能说明系统瓶颈、模块间相互影响，以及结论适用的配置、workload 和误差范围 |

保留独立的 NoC 学习支线：掌握基本请求、响应和反压后，进入 Garnet，研究小型拓扑中的 VC、credit、Buffer、仲裁和拥塞。它可以与内存、简单 SoC 学习交叉推进；通用 DMA 的起步不依赖先完成 NoC。gem5 Port 的 retry 与 Garnet 的 credit 分别理解。

涉及 OS、驱动、命令提交和设备中断的研究，再引入 FS 及相应软件栈。组合模块时，明确每个新增模块回答的问题和连接依据，不照搬资料目录作为硬件拓扑。

## 每轮怎样推进

**明确问题与范围 → 解释相关机制 → 选择最小模型 → 提出预期 → 做对照实验 → 检查与解释结果 → 记录结论及边界。**

- 先确定一个可以回答的问题，例如“提高请求注入率后，完成吞吐为什么不再增加”。
- 优先使用现有组件。官方组件加配置和分析即可回答问题时，就以此完成实验；发现缺失的关键行为后再新增模型。出现实际复用需求后，再提取通用组件或工具。
- 运行前写出可能的瓶颈、带宽上限和变化方向；运行后解释偏差，不能只展示曲线。
- 验证与目标相称，检查功能、时间、有限资源、请求返回和完成条件；正常退出只是运行成功的一项证据。
- 每轮留下机制说明、可复现的配置或必要模型、实验依据、结论和限制。无需每轮都新写模型或新建专题笔记。

具体运行身份、测量区间、输出保留和验证要求复用 [实验工作方法](../methods/experiment-workflow.md)，不再建立第二套记录制度。

## 第一个性能实验

研究问题确定为：**请求注入率与完成吞吐的关系。**

| 项目 | 初始安排 |
| --- | --- |
| 系统 | 单一流量发生器连接 SimpleMemory，先研究清楚基本服务能力 |
| 固定条件 | 顺序只读、固定请求大小、地址范围、内存延迟、内存带宽和测量规则 |
| 对照变量 | 请求注入率，覆盖低于、接近和高于配置服务能力的情况 |
| 观察内容 | 配置注入率、实际接纳与完成情况、完成吞吐、请求延迟和积压情况；先核对统计定义与可用性 |
| 验证重点 | 吞吐是否受到服务能力限制，反压怎样影响请求产生与完成，测量结束时的未完成请求是否影响解释 |
| 接续问题 | 在足够的请求供给下，单独改变 outstanding 上限，研究并发请求数与吞吐的关系 |

官方内存流量示例用于学习搭建方式；首个机制实验使用较简单的内存模型，之后再引入详细 DRAM，逐项研究额外因素。该实验不作为 DMA 搬运或目标硬件性能的替代验证。实施时在实验正文中固定数值参数、统计口径和停止规则，实际配置以各次运行记录为准。

## 与研究计划的配合及近期顺序

研究计划负责建立对工具的认识，本计划负责通过使用和实验形成建模能力。实验中出现的问题，反过来推动少量、有针对性的资料和源码阅读。

1. 依据研究计划审阅现有工作笔记，优先补齐整体关系和两个示例的讲解。
2. 准备运行环境，完成官方小例子的真实运行与输出解释。
3. 开展首个注入率实验，再进入 outstanding 等单一机制研究。
4. 根据实验中暴露的问题，选择后续简单 SoC、NoC 或 DMA 专题。

soc_study 提供模块职责和架构资料，本项目负责相应的模型与实验；按问题引用已有资料，不复制或重整整套来源库。教学模型、gem5 参考实现和目标硬件事实始终分开标注。

文件与模型仍按项目已有职责组织。计划描述后续工作，不代表构建、运行或各阶段已经完成；实际状态只在进度与实验记录中维护。
