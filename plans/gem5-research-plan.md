# gem5 研究计划：先建立整体认识

修订日期：2026-10-12。依据用户确认的修订稿，将第一次研究计划与后续优化建议整合于此。

本文件只负责“先研究 gem5 的哪些内容、研究到什么程度”。围绕项目目标怎样开展模型和实验，见独立的 [项目工作开展计划](project-work-plan.md)；实际完成情况见 [当前进度](../records/PROGRESS.md)。

## 目标与起点

建立对 gem5 构成、特征、运行过程和建模能力的整体认识，能够判断一个简单问题应该从哪些组件入手。

以官方资料、配置示例和少量重要源码为主，源码阅读围绕具体疑问展开。现有 [工作笔记](../records/WORKING_NOTES.md) 已覆盖不少内容，后续以审阅、补充和串联为主；已有 [仓库目录导读](../notes/gem5-repository-map.md) 继续承担目录说明，不重复逐目录调查。

## 研究顺序与产出

| 顺序 | 研究内容 | 具体做法 | 形成的结果 |
| --- | --- | --- | --- |
| 1. 建立整体框架 | gem5 是什么，工程各部分如何分工 | 复用现有仓库导读，说明仿真内核、系统组件、Python 配置、stdlib、workload、统计工具之间的关系，以及官方源码、教程、文档、资源库各自的用途 | 一张整体组成图和简要说明 |
| 2. 从简单系统理解工作过程 | 一个配置怎样变成仿真系统 | 先讲解官方简单 CPU 配置，再对照无 CPU 的内存流量示例；标出组件、连接、参数、输入、启动入口和预期输出 | 两个示例的结构图，以及“配置—运行—输出—分析”的流程 |
| 3. 结合示例认识主要特征 | gem5 有哪些重要选择，各自影响什么 | 解释离散事件、Python/C++ 分工、ISA 与 CPU 模型、SE/FS、Timing/Atomic/Functional，以及仿真时间与宿主机耗时；说明 stdlib 如何组织已有模型 | 特征及适用场景对照表 |
| 4. 认识主要模块及边界 | 有哪些组件可以用于 SoC 研究 | 概览 CPU、Cache、内存、互连、地址翻译、设备和 DMA；分清 Classic、Ruby、Garnet 的职责与关系 | “组件解决什么问题、处于什么位置、有哪些限制”的能力地图 |
| 5. 选读少量关键源码 | 配置中的对象怎样协作 | 围绕 SimObject、事件调度、Port 请求与响应，按需要查看关键定义或短例子；理解对象、时间和请求之间的关系 | 一份能连接配置与实现的简短说明 |
| 6. 联系本项目的研究问题 | 已有能力怎样支持 SoC/SDMA 学习 | 分别以简单 SoC、内存性能、NoC、DMA 为例，列出可用组件、需要补充的假设和尚待验证的行为 | 后续专题的选择依据 |

先用一个简短框架建立位置感，再尽早进入两个具体示例。后续概念解释回到示例，不把全部术语作为阅读配置的前置课程。

## 资料与源码阅读边界

- 两个配置示例是主要入口：主实验基线中的 `configs/learning_gem5/part1/simple.py` 与 `configs/example/gem5_library/memory_traffic.py`。首先理解它们表达的系统、参数和输入输出。
- SimObject、EventQueue、Port 的源码作为解释问题的辅助材料，不把两个示例和三个头文件变成必须逐行读完的清单。必要时用短小的事件示例补充解释。
- CPU 流水线、Cache 一致性协议、DRAM 调度和 SDMA 命令实现，留到相应问题出现后再深入。
- 使用 [上游登记](../upstream/README.md) 中的固定版本。Bootcamp 保留课程基线；教程接口与主实验基线不一致时，回到对应版本核对。
- 阅读记录区分正文阅读、标题或目录浏览、源码选读和实际运行。编译与仿真不作为本阶段资料阅读完成的前提。

## 完成判断

1. 能指出简单配置中的组件、连接、workload 和输出，并解释它们如何配合。
2. 能说明带 CPU 与不带 CPU 的两个示例分别适合回答什么问题，以及省略 CPU、Cache 或 OS 后不能回答什么。
3. 能区分系统运行方式、访存方式和模型精度，并说明 stdlib 负责组件组织与运行控制。
4. 面对一个简单的内存或 DMA 问题，能够提出初步组件选择，并指出尚未验证的假设。

检查以讲解配置、对照示例和提出一个简单建模方案为主。笔记写齐不自动等于使用者已经掌握；实际运行能力由项目工作计划验证。
